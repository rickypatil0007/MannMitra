# 02 Ux Principles
# MANNMITRA — UX PRINCIPLES

---

# 1. REDUCE COGNITIVE LOAD

Students may already be under academic or emotional pressure.

Every screen should minimize unnecessary decisions.

---

# 2. ONE PRIMARY ACTION

Every important screen should have one obvious primary action.

Secondary actions should visually recede.

---

# 3. PROGRESSIVE DISCLOSURE

Do not expose every capability immediately.

Show what the student needs now.

Reveal advanced functionality when relevant.

---

# 4. CONTEXT OVER COMPLEXITY

The interface should adapt to context.

Example:

Instead of showing every planner feature:

"Your exam is Friday. You have 3 tasks left."

Then provide:

"Plan my week"

---

# 5. SUPPORT WITHOUT PRESSURE

MannMitra should suggest rather than force.

Use language such as:

"Would you like to..."

rather than:

"You must..."

---

# 6. MAKE THE NEXT STEP OBVIOUS

The user should rarely wonder:

"What do I do now?"

---

# 7. EMOTIONAL SAFETY

Avoid interfaces that make users feel:

- judged
- monitored
- behind
- guilty
- unsuccessful

---

# 8. NO TOXIC PRODUCTIVITY

Do not glorify:

- endless work
- streak preservation
- excessive task completion
- lack of rest

Rest is a valid part of wellbeing.

---

# 9. CALM INFORMATION DESIGN

Information should arrive at the right time.

Avoid notification overload.

Avoid dashboard overload.

Avoid unnecessary charts.

---

# 10. HUMAN LANGUAGE

Use language that sounds like a thoughtful human.

Prefer:

"Looks like this week is getting busy."

Instead of:

"Stress threshold exceeded."

---

# 11. USER CONTROL

Students should understand and control:

- privacy
- notifications
- sharing
- community participation
- AI context
- personal data

---

# 12. TRUST THROUGH EXPLANATION

When appropriate, explain:

why something is shown
why something is recommended
what information is being used

---

# 13. FAILURE SHOULD FEEL SAFE

If something breaks, the interface should maintain trust.

Never expose technical implementation details unnecessarily.

---

# 14. CONSISTENCY

Similar actions should behave similarly throughout the product.

---

# 15. ACCESSIBILITY FIRST

Do not design inaccessible interactions and fix them later.

Accessibility must be considered from the beginning.

---

# 16. MOBILE-FIRST THINKING

The most important student workflows should work beautifully on
small screens.

---

# 17. QUIET PREMIUM

The product should feel expensive because of:

- spacing
- typography
- precision
- consistency
- restraint

not because of:

- gradients
- animation
- visual effects
- excessive decoration

---

# 18. NO DARK PATTERNS

We strictly forbid any dark UX patterns.
- Do not trick students into sharing data.
- Do not make account deletion difficult.
- Do not use false urgency (e.g., "3 people are doing this task right now!").
- Do not use guilt trips to encourage app usage.
