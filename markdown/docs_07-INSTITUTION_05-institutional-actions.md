# Institutional Actions

## 1. Purpose
Defines the tools and workflows available to institutional administrators to take proactive, systemic actions based on the insights generated by the MannMitra platform.

## 2. Scope
Covers broadcast messaging, resource allocation, and policy adjustments that can be triggered from the Institution Dashboard.

## 3. Actors
- **Institution Admin / Dean**: Reviews insights and triggers actions.
- **Student**: Receives broadcast support or benefits from systemic changes.

## 4. Requirements
- The dashboard must provide a mechanism to send targeted, supportive broadcasts to specific cohorts (e.g., "To all 3rd-year Engineering students: The counselling center has opened drop-in hours this Thursday ahead of midterms").
- Broadcasts must be clearly marked as "Institutional Announcements" to distinguish them from AI or peer messages.

## 5. User Flow
1. **Insight Review**: Admin notices a sharp spike in the Academic Pressure Index for the School of Architecture.
2. **Action Selection**: Admin clicks "Take Action" next to the insight.
3. **Resource Deployment**: Admin selects "Broadcast Support Resources".
4. **Drafting**: Admin drafts a supportive message and attaches a link to a campus wellness event.
5. **Dispatch**: The message is sent as an in-app notification to the affected cohort.

## 6. UI / UX Behavior
- **Action Buttons**: Placed contextually next to the data charts.
- **Preview**: A WYSIWYG preview of how the notification will look on the student's mobile device before sending.

## 7. Functional Behavior
- **A/B Testing (Future)**: The system can track the engagement rate (click-throughs to the resource) of different institutional actions to measure their effectiveness in reducing cohort stress.

## 8. Security / Privacy
- Actions are one-way broadcasts. Admins cannot see which specific students read the message, only aggregate read receipts (e.g., "60% of cohort viewed").

## 9. Error Handling
- Prevent spam: Rate limiting prevents an admin from sending more than 2 institutional broadcasts to the same cohort within a 24-hour period.

## 10. Testing
- Verify that a broadcast targeted at Cohort A does not appear in the notifications of a student in Cohort B.
